# Vibe Walking 一期实施方案

依据 [项目初始设计](20261122-bootstrap.md)。静态资源构建、浏览器能力和模型协议的依据见[一期技术调查](../research/20261122-phase-one-dependencies.md)。

## 一期交付

1. **游玩**。打开页面直接看到唯一的内置关卡「走到红色按钮」。玩家在左侧发消息，Agent 在右侧读图、移动角色并踩下按钮。页面显示对话、工具调用及通关结果，可随时重置。
2. **创作**。从同一关卡的副本开始。创作者可以绘制地形、放置按钮、拖动出生点，设置关卡名、重力、惯性和系统提示词，通过键盘或 Agent 试玩，并在本地恢复草稿、导入和导出 YAML。
3. **本地运行**。运行 `vibe-walking` 启动本地 Web 服务。Go 二进制内嵌前端资源，在同一监听地址提供页面、设置 API 和模型代理。支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages，通过设置选择一种协议和模型。

页面顶部提供「游玩」「创作」两个入口。首关只需要向右走。创作者可以用一格高的方块验证跳跃和碰撞。一期聚焦桌面浏览器和中文界面。封面、关卡列表、完整设置页、上下文压缩、斜面及动态机关后续实现。

## 启动与构建

```sh
vibe-walking                      # 监听 127.0.0.1:2333 并打开浏览器
vibe-walking -l :80               # 监听 0.0.0.0:80
vibe-walking --open-browser=false # 启动服务并在终端输出访问地址
```

- 复用 `internal/commands` 的 Cobra 根命令。在 `Options` 加入 `-l` / `--listen` 和默认开启的 `--open-browser`，将 `RunE` 接到 Web 服务。监听地址中的空主机名归一为 `0.0.0.0`。先绑定端口，再显示访问地址并打开浏览器。监听通配地址时，浏览器使用对应端口的回环地址。macOS 使用 `open`，Linux 使用 `xdg-open`。浏览器打开失败时保留服务并提示访问地址。已有的退出信号上下文用于取消上游请求并关闭 HTTP 服务。
- TypeScript 项目仍以仓库根目录为根。`index.html`、`package.json`、`tsconfig.json` 和 Vite 配置均在根目录，`build.outDir` 设为 `internal/web/dist`。在 Node.js 22.12 或更高版本下，从根目录依次运行 `npm ci`、`npm run build`、`go build ./cmd/vibe-walking`。`internal/web` 用 `//go:embed dist` 和 `fs.Sub` 提供静态资源，保留现有的 `dist/` 忽略规则。
- 发布流程在 GoReleaser 编译前运行前端构建，并按 `go.mod` 安装 Go 工具链。将 `.goreleaser.yaml` 和 `scripts/install.sh` 中的 `vieb-walking` 拼写统一为 `vibe-walking`，对齐实际命令目录、发布产物、安装路径和 Dockerfile。
- `internal/server` 在同一 HTTP 监听上挂载 `/`、`/api/v1/`、`/llmproxies/`，其中 `/` 由 `internal/web` 提供静态资源处理器。页面用相对地址请求设置和代理。`#/play` 和 `#/create` 由前端处理，刷新均从 `/` 取得嵌入的 `index.html`。未知 API 或代理路径返回 `404`。

## 模型设置与代理

复用 `pkg/config` 的 `Config`、`ModelConfig` 与三个 `ModelAPIProtocol` 常量。一期每个进程使用一份当前模型配置。设置保存在[数据目录](20261122-data-directory-and-install.md)下的 `settings.json`。文件格式沿用现有 JSON 字段。

```json
{
  "model": {
    "api": "OpenAIResponses",
    "baseURL": "https://api.openai.com/v1",
    "model": "<模型 ID>",
    "apiKey": "<用户提供的密钥>"
  }
}
```

### 设置 API

| 路径 | 契约 |
| --- | --- |
| `GET /api/v1/settings` | 返回 `{ "model": null }` 或带 `api`、`baseURL`、`model`、`hasAPIKey` 的模型对象，供页面加载协议和展示设置。 |
| `POST /api/v1/settings` | 接收 `{ "model": { "api": "…", "baseURL": "…", "model": "…", "apiKey": "…" } }` 保存模型配置，`{ "model": null }` 清除。成功返回 `200` 和与 `GET` 相同的摘要，非法数据返回 `400`，保存失败返回 `500`。 |

- 「模型连接」面板包含协议、Base URL、模型 ID 和 API Key。选择 OpenAI 协议时默认 `https://api.openai.com/v1`，选择 Anthropic 时默认 `https://api.anthropic.com/v1`。Base URL 为含 API 路径前缀的 HTTP(S) 地址，不带用户名、密码、查询参数或片段。模型需支持所选协议下的图片输入和函数调用。
- `apiKey` 省略时，仅在协议与规范化后的 Base URL 均相同时保留旧密钥。切换协议或地址时，省略密钥表示新连接使用空密钥。空字符串显式清除密钥。浏览器只在设置提交中发送用户输入的密钥，设置摘要仅返回 `hasAPIKey` 表示是否有密钥。
- 实现现有 `LoadConfig` 和 `SaveConfig`。文件缺失时使用空配置，无法读取或解析时报告文件路径。配置更新串行化，在同目录用临时文件和重命名提交。配置目录和文件新建权限分别为 `0700`、`0600`。写入成功后发布内存快照，失败时继续使用上次有效配置。重启时从文件恢复。

### LLM 代理

三个入口均接收最大 32 MiB 的 `POST` JSON。Go 以当前设置启用对应路径，按表格将后缀拼接到 Base URL，保留已有路径前缀。

| 配置中的 `api` | 代理路径 | 上游后缀 | Go 设置的上游请求头 |
| --- | --- | --- | --- |
| `OpenAIChatCompletions` | `/llmproxies/chat/completions` | `/chat/completions` | `Authorization: Bearer <API Key>` |
| `OpenAIResponses` | `/llmproxies/responses` | `/responses` | `Authorization: Bearer <API Key>` |
| `AnthropicMessages` | `/llmproxies/messages` | `/messages` | `x-api-key: <API Key>`、`anthropic-version: 2023-06-01` |

- 每次代理请求从一份已提交的配置快照取得协议、上游地址、模型 ID 和密钥。未配置或请求其他协议时返回 `404`，错误代码分别为 `model_not_configured` 和 `proxy_not_enabled`。已启用的入口收到非 `POST` 请求返回 `405`，收到无效 JSON 对象返回 `400`。Go 以配置中的模型 ID 填写请求体的 `model`，其余协议字段原样转发，密钥为空时省略鉴权头。上游请求只使用代理明确设置的头，目标 URL 取自设置，禁止跟随重定向。
- 代理保留上游响应状态和 `Content-Type`，转发响应体。请求上下文随浏览器断开和服务退出而取消，上游请求期限为 60 秒。代理生成的错误使用 `{ "error": { "code": "…", "message": "…" } }`，上游不可达返回 `502`，超期返回 `504`。日志只记录协议、状态和耗时。浏览器呈现可读错误，编辑和手动试玩可独立使用。
- 对设置写入和模型代理应用 `http.CrossOriginProtection`，默认回环监听时只接受回环 `Host`。通配监听时，能访问监听地址的客户端共用该进程的设置和模型额度。

## 页面与流程

| 页面 | 布局和操作 |
| --- | --- |
| `#/play`（默认） | 左栏约三分之一，包含消息输入、对话与动作记录。右栏为完整关卡画面，顶部有暂停、重置和模型连接入口。通关或失败显示结果及重置入口。 |
| `#/create` | 左栏编辑关卡名和系统提示词，中央是带网格的可编辑画面，右栏为方块工具和物理参数。顶部提供导入、导出、手动试玩和 Agent 试玩。 |
| 创作中的试玩 | 从当前草稿创建一次独立的关卡运行。手动模式左栏显示实时动作 JSON，Agent 模式左栏切换为对话并显示模型连接入口。均提供重开和返回编辑。试玩结束回到原草稿。 |

画面按 16:9 比例在可用空间内等比居中。地形为深色像素块，角色为浅色方块配两条眼睛，眼睛朝向最后一次水平位移方向，红色按钮压下时变矮。配色、大色块和角色参考[原始设计的风格图](image/style.jpg)。一期用固定的栏宽比例。

暂停菜单提供继续、重置和返回导航的操作。暂停或页面隐藏时冻结物理和动作队列，清空手动按键状态。已发出的模型请求可返回，响应在恢复后才处理。重置和切换页面销毁旧运行、动作队列及对话，取消挂起请求。试玩重开使用进入试玩时的同一草稿副本。

## 关卡数据

仓库根目录下的 `levels/meta.json` 是条目数组。一期条目为 `{"id":"0001","name":"走到红色按钮","definition":"0001-walk-to-button.json","description":"引导角色向右走到红色按钮。"}`。`definition` 是 `levels/definitions/` 下的文件名，编译时打包这些 JSON 文件。 `id` 用于记录内置关卡进度，目录中的 `name` 与定义文件的 `name` 一致。

`levels/definitions/0001-walk-to-button.json` 的完整内容如下。

```json
{
  "schemaVersion": 1,
  "name": "走到红色按钮",
  "tiles": [
    "................",
    "................",
    "................",
    "................",
    "................",
    "................",
    "................",
    "............B...",
    "################"
  ],
  "spawn": { "x": 2, "y": 7 },
  "gravity": 1,
  "inertia": 0.5
}
```

- 左上角为 `(0, 0)`，`x` 向右、`y` 向下。`tiles` 恰好 9 行，每行 16 格。`.` 是空格、`#` 是实心地形、`B` 是红色按钮。`spawn` 为角色左上角的整数格坐标，所在格必须为 `.`。
- `schemaVersion` 固定为 `1`。`name` 去首尾空白后长 1～80 字符。可选 `systemPrompt` 最多 4096 字符，有非空白文本时原样覆盖默认提示词。`gravity` 和 `inertia` 为有限数，范围分别为 `[-10, 10]`、`[0, 10]`，缺省分别为 `1`、`0.5`。
- 可玩关卡恰有一个 `B`。按钮沿重力方向相邻格必须是 `#`，重力为零时使用下方。结构校验用于加载和保存草稿，可暂缺按钮或支撑。启动试玩、导出、导入发布关卡和加载内置关卡时，还需通过可玩校验。校验检查格式和可运行条件，关卡能否走通由创作者试玩确认。
- YAML 与内置 JSON 表达同一份 `LevelDefinition`。导入单个最大 64 KiB 的 `.yaml` 或 `.yml` 文档，拒绝重复键、未知字段、别名和自定义标签。解析并校验成功后替换当前草稿。失败时指出字段或地图位置并保留当前草稿。导出为 `level.yaml`，重新导入应得到相同的标准化数据。

## 关卡运行规则

**时间与碰撞。** 角色碰撞盒为 `1×1` 格。物理每 `10 ms` 更新一次，画面由 `requestAnimationFrame` 绘制，通过累积时间驱动物理步进。单帧最多补 `100 ms`，恢复时从新帧开始计时。等待模型时物理继续运行。每步更新顺序为读取输入和起跳、水平移动与碰撞、更新竖直速度、竖直移动与碰撞、判定通关或失败。两轴分别将位移截到最近碰撞面，侧边限制在地图宽度内。竖直两端开放，角色整个碰撞盒离开画面则失败，重置后回到出生点。

**重力与跳跃。** 向下重力为 `16 × gravity` 格/秒²，竖直速度绝对值上限为 `20` 格/秒。默认跳跃初速度约为 `6.93` 格/秒，方向与重力相反，重力为零时向上。默认上升约 `1.5` 格。每次落到重力侧的支撑面时补充一次跳跃机会，出生时有一次。从平台边沿走出后仍可消耗这次机会，在相反方向撞到地形时只清零竖直速度。零重力用下方接触判定支撑。

**横向位移与惯性。** 有方向输入时速度为 `4` 格/秒。指令距离代表预定输入量，受阻仍消耗该量。输入从移动变为空闲时，沿原方向以相同速度继续移动最多 `inertia` 格，遇障碍提前停止。连续同向输入合并为一段，相反方向输入立即结束原方向滑行，按新方向开始移动，松开后计算新方向的滑行。

**按钮。** `B` 靠着重力侧的支撑面绘制，突出 `0.15` 格，压下后为 `0.06` 格，水平有效区宽一格。角色在按钮支撑面的接触一侧落地或沿该面走入，且与按钮有正的水平重叠，立即通关。按钮本身无实心碰撞盒，穿过上方、仅擦边或从支撑背面碰到地形都不触发。通关或失败后冻结关卡，清空后续动作。内置关卡只有游玩模式的首次通关计入进度。

## 动作、手动试玩和记录

`ExecActionSequence` 接收 `{ "actions": [...] }`，使用以下四种动作。整个序列先校验，再从头执行。成功执行返回 `Ok`。若中途通关或失败，关卡在当步终止并返回 `Ok`，后续可用 `ReadScreen` 查看终态。

| 动作 | 参数 | 执行 |
| --- | --- | --- |
| `jump` | 可省略 `value`，提供的数值被忽略 | 在当步尝试起跳并立即进入下一动作。跳跃机会已耗尽时跳过。 |
| `moveLeft` / `moveRight` | `value` 为 `0.01`～`24` 格，最多两位小数 | 每步消耗最多 `0.04` 格，最后一步只消耗剩余量。下一段从下一物理步开始。 |
| `sleep` | `value` 为 `0.001`～`10` 秒，最多三位小数 | 转成向上取整的物理步数，期间方向输入为空，物理与惯性继续。 |

每次调用允许 `1`～`32` 个动作，按物理步换算总时长最多 `30` 秒。校验后把移动量和等待时间分别换成整数百分之一格和毫秒，再按步调度。序列末尾释放方向，剩余惯性由物理自行更新。整包格式或范围错误时，返回带原因的错误且该包零动作生效。相邻同向移动即使之间有瞬时 `jump`，也按持续输入处理。

手动模式接受 `A/左`、`D/右` 和 `W/上/空格`。每步采样按住的方向，两侧同时按下视为空闲。跳跃只在逻辑按键由松开变为按下时触发，切换键位和系统键盘重复事件均按逻辑按键状态处理。游玩和 Agent 试玩的键盘事件不会进入输入层。

手动试玩从重开后的第一个物理步记录有效输入。以方向变化或跳跃事件切段，将移动步数乘 `0.04` 作为动作距离，空闲步数乘 `0.01` 作为 `sleep` 秒数。起跳事件排在该步对应的移动或等待之前。左栏随试玩更新 JSON 并支持复制，超出单次调用限额时标明。可用一段合法的记录从相同初始状态重放相同的输入轨迹。试玩和录制一同暂停。

## Agent 与三种模型协议

> 此处记录一期设计。当前默认提示词的用户名模板、流式生成、工具循环、中断与上下文压缩见 [Vibe 对话与模型设置](20261122-vibe-conversation.md)。

默认提示词如下。自定义提示词随关卡保存，启动 Agent 时读取，发送消息时传给当前模型。

> 你操控画面中有两只眼睛的浅色方块。玩家通过对话给你指引。目标是踩下红色按钮。用 ReadScreen 观察完整画面，用 ExecActionSequence 执行移动、跳跃或等待。移动距离以角色边长为一格。需要行动时先看画面，行动后按需再看画面，向玩家简短说明结果。

### 共用的工具循环

- `ReadScreen` 接收 `{}`。使用当前世界快照重绘游戏场景，按比例生成 `910×512` 的 PNG，画面只包含角色、地形和按钮。`ExecActionSequence` 使用前述动作格式。两种工具均在浏览器内校验和执行。
- 浏览器的 Agent 共用一套回合调度和工具执行器。三个协议适配器负责生成各自的请求体，读取文本和工具调用，编排协议原生历史及工具结果。Go 代理使用各协议的上游格式转发。对话区域展示玩家消息、模型回复和工具事件。
- 一期使用非流式响应，同时只处理一条玩家消息。每条最多八次模型请求，若执行到第八次则禁用工具以取得最终回复。每次响应允许零或一次工具调用，收到多次调用或截断的调用时结束本轮并显示错误。工具执行完再发下一次请求。非法参数、未知工具或终态中的动作调用返回工具错误。终态仍可在当前轮读图或汇报结果，重开后可发新消息。
- HTTP 失败、超时或响应未完成时结束本轮并显示原因。历史按完整的调用和结果成组提交，保留已经执行的动作，下一条玩家消息可继续。重置、返回编辑或切换页面时取消旧请求。设置保存成功后，取消当前请求和动作序列，保留画面位置并开启新会话。处理异步响应前检查会话标识。

### 协议适配

**OpenAI Chat Completions。** 从 `choices[0].message` 读取文本或 `tool_calls`，保留助手消息。关卡提示词作为 `developer` 消息，函数在 `tools[].function` 声明，关闭并行调用，收尾时用 `tool_choice: "none"`。工具结果使用 `role: "tool"` 与 `tool_call_id`。`ReadScreen` 先写入文本结果 `Ok`，随后在同一次请求的 `messages` 中附加一条 `role: "user"` 的截图消息，包含说明文字和 `type: "image_url"` 的 PNG Data URL。对话区把这条合成消息显示为工具事件，玩家消息仍由输入框产生。

**OpenAI Responses。** 设置 `instructions`、`store: false` 和 `parallel_tool_calls: false`，函数直接在 `tools` 声明，收尾用 `tool_choice: "none"`。从 `output` 读文本和 `function_call`，依原顺序保留输出项及携带加密内容的推理项，通过 `input` 重放历史。工具结果用 `function_call_output` 和原 `call_id`，`ReadScreen` 的 `output` 为 `input_image` 数组项，`image_url` 传 PNG Data URL，`detail` 为 `auto`。两个 OpenAI 适配器的动作函数都显式设 `strict: false`，保留 `jump.value` 可省略的语义。

**Anthropic Messages。** 关卡提示词作为顶层 `system`，`max_tokens` 为 `4096`。函数使用 `tools[].input_schema`。`tool_choice` 设为 `{ "type": "auto", "disable_parallel_tool_use": true }`，收尾改为 `{ "type": "none" }`。收到 `stop_reason: "tool_use"` 时保留助手的 `content` 块并读取 `tool_use.id` 和 `input`。紧接一条以 `tool_result` 开头的 `user` 消息，结果的 `tool_use_id` 对应原调用，失败时带 `is_error: true`。`ReadScreen` 在该结果的 `content` 中附 `image`，`source` 使用 `type: "base64"`、`media_type: "image/png"` 及不含 Data URL 前缀的 `data`。

## 草稿和本地存储

- 画笔可选择实心块、按钮或橡皮。点击着色，拖动连续涂画实心块或擦除。按钮在空格中放置，成功移动时清除原来的按钮。出生点拖到空格后吸附到格子。按钮与出生点互斥，实心画笔遇到它们时保留原格并提示。
- 第一次打开创作时复制内置关卡。草稿使用 `localStorage` 键 `vibe-walking:v1:draft` 保存，地图笔划提交、字段提交、拖动结束和成功导入时写入。缺按钮等可玩性错误会标明位置，并阻止试玩或导出，修正后恢复这些操作。
- 模型设置由 Go 持久化。设置面板用遮蔽输入接收密钥，并通过「清除连接」清除配置。浏览器本地存储用于草稿和进度，密钥与关卡 YAML、对话事件均独立。
- 内置关卡进度使用 `vibe-walking:v1:progress`，内容为 `{"0001":{"completedAt":"<ISO 8601 时间>"}}`。读取失败时使用内置关卡副本或空进度。写入失败时显示提示，本次运行仍可编辑和导出。每次刷新从出生点开始，对话、动作记录和截图只留在当前运行内存。

## 实现顺序和模块边界

前端采用 TypeScript、Vite、HTML/CSS 及 Canvas 2D，YAML 由 `yaml` 2.x 编解码。前端自动验收用 `npm test`，构建静态资源后用 `go test ./...` 验证 Go 模块。

| 步骤 | 模块边界 | 完成条件 |
| --- | --- | --- |
| 1. 本地启动与构建 | `internal/commands` 绑定启动参数，`internal/server` 管理监听和 HTTP 路由，`internal/web` 嵌入 Vite 生成的 `internal/web/dist` 并提供静态资源处理器。 | 用编译后的程序从其他目录启动，打开页面，三个命令用法和退出行为均符合预期。 |
| 2. 设置与代理 | `pkg/config` 读写配置，`internal/server` 的设置和代理处理器共享已提交的配置。 | 用三个测试上游分别校验 URL、模型字段、鉴权、切换和持久化。 |
| 3. 关卡内核与画面 | `src/level/` 提供结构校验、可玩校验和编码，`src/game/` 提供固定步更新、动作执行及快照，`src/render/` 复用绘制逻辑生成画面和截图。 | 脚本可让首关通关，截图中可见压下的按钮。 |
| 4. 编辑和手动试玩 | `src/editor/` 管理草稿和编辑操作，`src/storage/` 处理本地读写，页面负责从草稿创建或销毁试玩运行。 | 完成绘图、手动试玩、YAML 往返和刷新恢复。 |
| 5. 对话游玩 | `src/agent/` 实现共用的回合、工具分发和三个协议适配器，通过同源代理访问模型。 | 每种协议都能独立驱动首关通关，并在创作界面使用关卡提示词试玩。 |

## 验收场景

| 场景 | 操作和预期 |
| --- | --- |
| 首关核心玩法 | 打开游玩页，按右方向键，角色保持原位。发送「先看画面，再向右走到红色按钮」，Agent 读图后调用动作。测试模型返回 `moveRight(10)`，角色接触按钮即通关，压下的按钮出现在下一次截图中。重置后可重新对话，刷新后仍显示通关记录。 |
| 编辑并试玩 | 将出生点拖到 `(1, 7)`、按钮移动到 `(10, 7)`，在 `(5, 7)` 加一格实心块，修改关卡名、提示词和惯性。手动按右键会撞墙，再朝右跳可越过并踩下按钮。动作 JSON 随操作更新，回到编辑仍看到修改后的布局。进入 Agent 试玩时发送的系统提示词与编辑值一致，且沿用同一套碰撞。 |
| 回放与边界 | 同一试玩的短录制在相同起点重放，逐步状态一致。自动测试覆盖贴地走过按钮、从上方飞过、不同重力方向、撞墙仍消耗动作距离、空中一次起跳、暂停期间不推进和非法序列不执行。 |
| 本地保存和文件 | 导出关卡、刷新恢复、重新导入，比较标准化数据。导入非法 YAML 保留当前草稿。删除唯一按钮后可刷新恢复这个草稿，并在重新放置有支撑的按钮后继续试玩。创作试玩的通关结果不计入内置关卡进度。 |
| 启动与嵌入 | 验证默认监听和自动打开、`-l :80` 的 IPv4 通配监听、`--open-browser=false`、端口冲突和信号退出。将二进制放到没有前端文件的目录启动，确认 `/` 和静态资源可以正常访问。 |
| 设置与代理 | 依次保存三种配置并重启，验证 `$HOME/.vibewalking/settings.json`、设置摘要和每种协议的代理入口。测试上游应收到正确后缀、模型、鉴权头与版本头。旧路径停用，密钥未出现在设置响应中，保存失败保留旧配置。 |
| 三协议对话 | 对各协议构造「读屏 → 动作 → 再读屏 → 文本」上游响应，检查工具 ID、截图编码和提交顺序。Chat Completions 验证 `tool` 文本结果之后的截图消息，Responses 和 Anthropic 验证工具结果直接带图。再分别配置支持图像和函数调用的真实模型联调首关。 |
| 连接与中断 | 模拟上游鉴权失败、限流和超时，验证状态提示。重置、切换协议和离开试玩后，迟到响应无法执行旧动作。清除配置后仍可编辑和手动试玩。 |
