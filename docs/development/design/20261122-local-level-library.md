# 本地关卡库、游玩存档和 System Prompt

本文更新[游戏场景设计](20261122-game-scenes.md)中的关卡入口、存档、通关结算和 Vibe 交互约定。

## 关卡和进度

Go 的 `levels` 包管理两类关卡。内置关卡由 Go 嵌入，目录顺序决定下一关；自定义关卡写入[数据目录](20261122-data-directory-and-install.md)下的 `levels/<id>.json`。关卡文件和创作页导入、导出共用 `LevelDefinition` JSON 格式。可保存无按钮、按钮无支撑等创作中的草稿，关卡列表将其标记为待完善；导入、导出和正式游玩需要有可用按钮的关卡。创作试玩可直接运行草稿。JSON 文件只能通过校验后进入编辑器，失败时保留原有内容。

内置关卡依次为「01 走到红色按钮」「02 悬空起跳」「03 信任」，沿用这三张地图的自定义关卡顺序。三关使用各自的新 ID，旧内置关卡的通关记录和存档仍归属于原 ID。

数据目录下的 `progress.json` 保存各关首次通关时间、最佳通关耗时和未完成尝试。未完成尝试包含角色位置、朝向、速度、起跳状态、惯性状态和已经经过的计时。定期保存变化，离开关卡时保存最后状态，返回后恢复；离开关卡期间停止计时。死亡或通关清除本次尝试，重开从出生点重新计时。关卡物理定义变化时忽略旧尝试；名称和提示词修改不影响恢复。进行中的模型请求、动作队列、聊天历史和创作试玩仍在各浏览器页面的运行会话内。进度更新保留最早通关时间和最短用时，并按保存顺序忽略过期的尝试状态。关卡和进度文件都采用同目录临时文件写入后替换。

数据目录下的 `level-order.json` 保存自定义关卡 ID 数组，也采用临时文件写入后替换。读取目录时优先按该数组排序，跳过缺失和重复的 ID，再按文件名追加未登记的关卡。顺序文件缺失时按文件名排列，读取失败时沿用此顺序并显示警告。创建和迁移新增关卡时先登记到顺序末尾，再写入关卡定义。定义写入失败留下的 ID 会在读取时被跳过。

首次载入时，客户端尝试迁移当前浏览器来源可访问的旧草稿、首次通关记录、最佳耗时和最近内置关卡。草稿迁移到固定 ID，进度按最早与最短规则合并；服务器确认后清理对应的旧记录。其他浏览器来源的旧数据在其各自来源访问时迁移。

## 界面和 Vibe

关卡列表按内置、自定义两个标签页呈现。自定义页可以创建关卡，或者点击卡片右上角的铅笔图标进入创作。悬停图标显示「编辑」。创作页的返回入口回到自定义关卡列表。首页的「开始游戏」指向首个未完成的内置关卡，「继续游戏」恢复未结束的内置尝试。内置结算可返回首页，后面还有内置关卡时可进入下一关；自定义结算提供返回首页。首次游玩发现未配置模型时暂停当前画面并打开配置弹窗。路由切换保留回到页首的行为，标题、关卡预览和纯显示画布沿用原生的非聚焦行为。

自定义页有多张卡片时，可用卡片左上角的手柄将其拖到另一张卡片的位置，也可以聚焦手柄后用方向键前移或后移一位。服务端确认保存后更新卡片顺序，保存失败时显示错误并保留原顺序。

Vibe 同时指白色方块角色与对话对象，网页图标也使用这个角色。游戏画布随可用宽度按地图比例缩放，最大宽度为 1500 CSS 像素。对话和画面左右并排时，两个面板同高，历史消息在对话面板内滚动。窄屏上下排布时，对话面板使用独立高度。

死亡同步取消 Vibe 当前的模型请求和动作，并在关卡画面显示 Game Over 和「再来一次」。重开保留对话，下一条用户消息发送前添加 `<system-info>你刚刚坠入虚空，一阵眩晕之后，现在回到了原位置</system-info>` 及换行，聊天栏保留用户输入的原文。已完成的工具调用继续随会话发送，取消中的工具不会留下未配对的调用。

默认 System Prompt 只描述角色、工具用法和物理规律。创作弹窗以只读方式显示当前完整内容，点击编辑后可修改。保存写入当前完整文本，即使它与内置版本相同；重置恢复只读的内置文本，并移除关卡文件的 `systemPrompt` 字段。

## Go 接口

所有接口使用同源相对路径，并沿用服务的 Host 和跨来源写入保护。非成功响应沿用 `{ "error": { "code": "...", "message": "..." } }`。

| 方法与路径 | 作用 |
| --- | --- |
| `GET /api/v1/levels` | 返回按内置顺序排列的统一关卡目录与自定义关卡，含类别、定义和物理版本。单个损坏的自定义文件通过目录警告提示。 |
| `GET /api/v1/levels/{id}` | 获取一条关卡目录记录。 |
| `POST /api/v1/levels` | 提交空对象创建模板关卡；迁移可以通过 `legacy` 字段提交旧草稿。 |
| `PUT /api/v1/levels` | 提交 `{"ids":[...]}` 保存自定义关卡顺序，返回保存后的 ID 数组。请求必须恰好包含当前可读取的全部自定义关卡 ID。 |
| `PUT /api/v1/levels/{id}` | 提交不超过 64 KiB 的自定义关卡 JSON 定义并返回保存后的记录。 |
| `GET /api/v1/progress` | 获取最近内置关卡和按 ID 索引的游玩进度。 |
| `POST /api/v1/progress` | 合并旧浏览器存档。 |
| `PUT /api/v1/progress/{id}` | 提交指定关卡物理版本下的尝试快照，或清除尝试并提交通关耗时。物理版本已变化时返回 409。 |
