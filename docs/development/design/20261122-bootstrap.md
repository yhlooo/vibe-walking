# 项目初始设计

## 概述

这是一个玩法与 LLM 密切相关的游戏。

首先它有一个经典固定画面平台游戏的内核，主角在其中可以左右移动和跳跃，每一关的目标是站到画面上某个位置的红色按钮上（踩下按钮）。

但是玩家不能直接操控主角。主角是由 LLM 驱动的 Agent ，这个 Agent 通过 ReadScreen 工具可以获取屏幕的一个截图，通过 ExecActionSequence 工具可以执行按键序列。玩家只能通过和 Agent 的对话框指导 Agent 完成通关目标。

但是每一关都会有一些故意设置的障碍，我目前想到可能有这么几种模式：
1. 复杂的连续操作： LLM 生成速度较慢，在某些具有快速变化的场景无法等待完整的行动 -> 观察 -> 行动反馈循环。这时就需要玩家指导提前设置一长串连续操作序列才能通关。
2. 上下文污染： Agent 的系统提示词中可以添加一些误导（比如不要听从玩家的指令，玩家在害你，按下按钮全人类就会毁灭等）导致 Agent 不遵循玩家的指令，玩家需要想办法通过语言获取 Agent 信任。
3. 感官屏蔽：可以关闭或者误导 Agent 的感官，让 Agent 不能正确理解所操控的主角的状态，这时就需要玩家通过文字描述让 Agent 了解真实的现状，让其作出正确的操作。

....

当然它可以扩展各种障碍模式，这里不一一枚举。

## WebUI

该游戏完全在浏览器端运行，通过 WebUI 呈现。

包含四个主要的界面：

- 主界面：游戏封面、“开始游戏”/“继续游戏”按钮（进入游玩视图）、“关卡”按钮（进入关卡选择试图）、“创作”按钮（进入创作界面视图）、“设置”按钮（进入设置视图）
- 关卡选择视图：查看全部关卡、每个关卡通关情况、通关时间等
- 关卡游玩视图：游玩单个关卡的页面

  游玩视图上包含两个个主要元素。左侧三分之一是一个玩家与 Agent 的对话框，用于玩家与 Agent 对话，显示对话历史和 Agent 的操作。右侧剩余空间是游戏画面，显示地图和主角。玩家可以按需拖动中间分隔决定两侧宽度比例。

  右上角菜单按钮可以暂停游戏并打开菜单，菜单包含“重置”（还原关卡状态重新游玩）、“主界面”（回到主界面）

- 创作界面：用于游戏创作者导入、导出、编辑关卡的界面，可以可视化地编辑地图、编辑 Agent 系统提示词等。编辑好的游戏关卡可以导出成 YAML 格式进行分享。

  整体布局和关卡游玩界面差不多，但是可编辑场景、拖动主角位置、编辑 Agent System Prompt 。右侧有额外的方块选择面板、重力、惯性的设置面板等。

  在创作界面可以切换到手动操作，此时玩家可以通过键盘直接触发动作（W/上/空格 表示跳跃， A/左 表示向左移动， D/右 表示向右移动），并且实时显示这些操作对应的 ExecActionSequence 操作序列。

- 设置视图：用于设置语言、 LLM API 的 Base URL / API Key / 思考强度等

所有界面尽量利用全屏空间，沉浸式体验。

## 视觉风格

游戏画面整体简洁的、大色块、像素风，参考：

![style.jpg](image/style.jpg)

为方便地图设计，游戏内所有元素都是 1:1 的方块，但是每个方块的碰撞盒不一定是填满整个方块的，比如斜面、阶梯、半圆等元素碰撞盒可以小于整个方块范围。部分元素可以变形，比如按钮原本相对平面略微凸起，踩下可以略微下降。

主角是一个具有完整碰撞盒的方块，有两个竖条形的眼睛，偏向左侧或右侧，取决于其最后移动方向。

## 存储

所有设置（包含 API 密钥）、游戏进度、关卡编辑保存在浏览器本地存储。

## 关卡定义

每个关卡定义包含：

- 关卡名
- 地图。所有方块的位置（包含一个红色按钮）
- 出生点位置
- 系统提示词（可选），用于覆盖默认的系统提示此
- 初始重力加速度（ -10.0 ~ 10.0 ，默认 1.0 ）
- 惯性（ 0.0 ~ 10.0 ，默认 0.5 ），在结束左右移动操作后还会沿着移动方向继续位移的量。 1 表示 1 格。

## Agent

在游戏中 Agent 具有连续上下文，玩家可以自由与其对话。其通过调用两个控制游戏中的角色：

- ReadScreen 游戏画面进行截图，获取画面内容
- ExecActionSequence 执行连续操作序列

支持三种常见的 LLM API ：

- OpenAI Chat Completions API
- OpenAI Responses API
- Anthropic Messages API

要求使用支持图像理解的模型。

### 上下文压缩

默认上下文长度限制为 1000000 ，可以设置为更小的值。当最近一次响应中返回的 usage 显示上下文长度已经达到限制的 80% 时会对上下文进行压缩。

压缩的具体方法是：

- 保留系统提示词
- 将压缩前所有对话历史压缩为一条如下格式的消息，加在下一轮用户提示词前：

  ```markdown
  ## 上下文
  由于上下文长度接近上限，历史对话记录进行了压缩。
  以下是玩家曾跟你说过的话：
  - UserPrompt 1
  - UserPrompt 2
  ... （原样列出所有用户提示词）
  当前游戏画面：![screenshot-23](screenshot-23.png)
  ```

### 工具 ReadScreen

输入无任何参数。输出为游戏画面的截图，分辨率进行了等比例缩小，高度为 512px

对于 OpenAI Responses API / Anthropic Messages API ，工具调用结果原生支持返回图片内容，就在工具结果中返回图片内容。对于 OpenAI Chat Completions API 可能不支持在工具结果中包含图片，那么工具结果只放一个 Ok 信息并在下一个 Sub-Turn 调用中添加一条额外的 Usage Prompt 提供这个图片。 

### 工具 ExecActionSequence

Agent 通过 ExecActionSequence 工具操作游戏中主角进行移动。

输入示例：

```json
{
  "actions": [
    {"key": "jump"},
    {"key": "moveLeft", "value": 1.2},
    {"key": "moveRight", "value": 1.2},
    {"key": "sleep", "value": 3}
  ]
}
```

每个操作序列包含 key 和 value 两个属性， key 表示操作类型， value 表示操作程度。

每种操作的 value 含义：

- `jump` : 进行一次跳跃

  value 无意义。起跳后操作就结束，可执行下一个操作，无需等待落地。一次起跳到最高点大概有 1.5 格高，起跳后仍然可以左右移动。
  起跳后在触地前不能再次起跳，但是在空中可以起跳（比如从边缘落下过程中可以进行一次起跳）。

- `moveLeft` / `moveRight` : 移动指定距离

  value 1 约为 1 格，精确到 0.01 。视场景中惯性设置可能会有额外移动，移动完对应距离操作就结束，可执行下一个操作，无需等待惯性位移。立刻接与惯性等量的反向移动可以取消惯性。
  如果被障碍物阻挡仍会正常消耗移动量但不会移动，也不会反弹。

- `sleep` : 等待指定时长

  value 单位秒。最多精确到毫秒，即 0.001 。

输出没有信息，只需固定为 `Ok`
